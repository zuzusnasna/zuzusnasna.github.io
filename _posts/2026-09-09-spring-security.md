Spring Security를 공부하면서 인증과 인가를 구분했다.

## 인증과 인가

- 인증(Authentication) : 사용자가 누구인지 확인
- 인가(Authorization) : 확인된 사용자가 무엇을 할 수 있는지 판단

## UserDetailsService

로그인 과정에서 사용자 정보를 조회하는 역할을 담당한다.

## BCrypt

비밀번호를 평문으로 저장하지 않고 해시 방식으로 저장한다.

```java
passwordEncoder.encode(rawPassword);
```

## 배운 점

로그인 기능을 만든다는 것은 단순히 아이디와 비밀번호를 비교하는 것이 아니라 **사용자 확인 → 인증 정보 생성 → 권한 판단 → 요청 접근 제어**까지 이어지는 흐름이라는 것을 이해했다.

## 더 깊게 이해하기: 인증과 인가는 별개의 질문이다

인증(Authentication)은 요청 주체가 누구인지 확인하는 과정이고, 인가(Authorization)는 그 주체가 특정 자원에 접근할 수 있는지 판단하는 과정이다. 로그인 성공만 확인하고 모든 API를 허용하면 인증은 되어 있어도 권한 검증이 빠진 상태가 된다.

Spring Security의 필터 체인은 컨트롤러에 도달하기 전에 요청을 검사한다. 따라서 접근이 차단되었을 때 컨트롤러 로그가 남지 않을 수도 있다. 디버깅 시에는 URL 규칙, 필터 체인, 인증 객체, 메서드 보안 순서로 확인하는 편이 효율적이다.

### 보안 검증 체크리스트
- 로그인하지 않은 사용자의 보호 API 요청이 거부되는가?
- 사용자 A가 사용자 B의 식별자를 바꿔 요청했을 때 데이터가 노출되지 않는가?
- 프론트엔드에서 버튼을 숨기는 것과 서버에서 권한을 검사하는 것을 구분했는가?
- 인증 실패(401)와 권한 부족(403)을 의도에 맞게 구분하는가?
- 비밀번호와 토큰, 세션 식별자를 로그에 남기지 않는가?

보안은 화면의 로그인 상태가 아니라 서버가 매 요청에서 신뢰할 수 있는 근거로 권한을 확인하는지로 판단해야 한다.
