## 프로젝트 개요

3명이 함께 개발한 영화 예매 서비스다. 선호 영화관과 좌석을 기반으로 자동 좌석을 탐색하고, 원하는 좌석이 없으면 대기 등록 후 취소표 발생 시 자동 선점하도록 구성했다.

### 주요 기능

- 스마트예매 / 일반예매
- 5분 좌석 선점
- 취소표 대기 및 자동 선점
- Redis 기반 접속 대기열
- OAuth2 / JWT 인증
- SSE 실시간 알림
- QR 티켓 사용 처리
- k6 동시성·부하 테스트

## 담당 영역

로그인, 티켓 및 사용 처리, 취소표·접속 대기열, 동시성 제어와 성능 개선을 담당했다.

## 프로젝트에서 어려웠던 부분

### 1. 좌석 잠금 범위

처음에는 회차 전체와 좌석을 넓게 잠가 중복 선점을 막으려 했지만 서로 다른 구역의 요청까지 대기하는 문제가 있었다.

그래서 후보를 먼저 조회하고 **회차·구역 → 실제 선택 좌석** 순서로 잠금 범위를 좁혔다.

### 2. 취소표 이벤트 유실

취소와 후속 배정을 한 요청에서 모두 처리하면 트랜잭션이 길어지고 서버 중단 시 후속 작업이 누락될 수 있었다.

이를 해결하기 위해 좌석 변경과 Outbox 이벤트를 같은 트랜잭션에 저장하고 워커가 이벤트를 처리하도록 분리했다.

### 3. Redis 대기순번의 오래된 값

Redis Sorted Set만 믿으면 변경 반영 지연으로 오래된 순번을 보여줄 수 있었다.

DB와 Redis의 버전을 비교한 뒤 유효한 경우에만 `ZCOUNT`를 사용하고, 불일치나 Redis 장애 시 DB를 기준으로 계산하도록 했다.

### 4. 대규모 접속 제어

조회 최적화만으로는 동시에 몰리는 요청을 감당하기 어려웠다. Redis 대기열과 동시 입장 정원·초당 입장 한도를 적용하고 Lua로 입장권 발급을 원자적으로 처리했다.

## 배운 점

이 프로젝트에서 가장 크게 배운 것은 **동시성 문제는 단순히 `synchronized`를 붙이는 것이 아니라 잠금 범위, 트랜잭션 길이, 이벤트 처리 위치까지 함께 설계해야 한다**는 점이다.
