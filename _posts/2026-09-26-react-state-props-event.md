React를 처음 사용할 때 가장 많이 헷갈렸던 부분은 Props와 State의 차이였다.

## Props

부모 컴포넌트가 자식 컴포넌트로 전달하는 값이다.

```jsx
function UserCard({ name }) {
  return <div>{name}</div>;
}

<UserCard name="홍길동" />
```

자식 컴포넌트가 받은 Props를 직접 변경하는 것이 아니라 부모가 새로운 값을 전달하는 구조다.

## State

컴포넌트 내부에서 변경되는 값을 관리한다.

```jsx
const [count, setCount] = useState(0);

setCount(count + 1);
```

State가 변경되면 React가 다시 렌더링한다.

## 실제 화면에서의 흐름

```text
부모 State 변경
      ↓
새로운 Props 전달
      ↓
자식 컴포넌트 렌더링
```

## 배운 점

React 화면을 직접 찾아서 바꾸는 방식보다 **데이터가 바뀌고 그 결과로 UI가 다시 그려진다**고 생각하는 것이 훨씬 편했다.

## 더 깊게 이해하기: 상태의 소유자가 중요하다

Props는 부모가 자식에게 전달하는 읽기 전용 입력이고, state는 컴포넌트가 관리하는 변경 가능한 UI 데이터다. 자식 컴포넌트가 부모의 값을 직접 바꾸는 대신 이벤트 콜백을 통해 변경 의도를 전달하면 데이터 흐름을 추적하기 쉬워진다.

여러 컴포넌트가 같은 값을 필요로 한다면 상태를 공통 부모로 올리는 방법을 먼저 고려할 수 있다. 반대로 모든 값을 최상위에 두면 관련 없는 컴포넌트까지 불필요하게 다시 렌더링되거나 코드가 복잡해질 수 있으므로 상태는 실제로 공유되는 범위에 둔다.

### 실습 점검
- 화면에 표시되는 값 중 state로 관리해야 하는 값과 계산해서 얻을 수 있는 값을 구분했는가?
- 배열이나 객체 state를 직접 변경하지 않고 새 값으로 교체하는가?
- 자식은 이벤트를 발생시키고, 상태 변경은 소유한 컴포넌트가 담당하는가?
- 같은 데이터를 state와 별도 변수에 중복 저장해 불일치가 생기지 않는가?

상태 관리의 핵심은 훅을 많이 쓰는 것이 아니라 **어떤 컴포넌트가 데이터의 진실한 원본을 소유하는지** 결정하는 일이다.
