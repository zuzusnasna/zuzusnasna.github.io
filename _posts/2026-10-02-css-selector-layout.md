CSS를 배우면서 처음 헷갈렸던 부분은 선택자와 레이아웃이었다.

## 선택자

```css
p { color: black; }
.notice { font-weight: bold; }
#login-form { width: 300px; }
```

태그 선택자는 같은 태그 전체에 적용하고, class는 여러 요소에 재사용하며 id는 특정 요소를 식별할 때 사용한다.

## Box Model

HTML 요소의 크기는 단순히 `width`와 `height`만으로 결정되지 않는다.

```text
margin
 └ border
    └ padding
       └ content
```

`box-sizing: border-box`를 사용하면 지정한 width 안에 padding과 border를 포함시킬 수 있어 화면 크기를 계산하기 편했다.

## Flex

```css
.container {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
```

가로 배치, 세로 정렬, 간격 조정처럼 실제 화면에서 자주 필요한 배치를 쉽게 만들 수 있었다.

## 배운 점

CSS는 속성을 하나씩 외우기보다 **요소의 크기 → 위치 → 정렬 → 반응형** 순서로 생각하면 문제를 해결하기 쉬웠다.

## 더 깊게 이해하기: 선택자와 레이아웃은 유지보수 비용에 영향을 준다

CSS 선택자는 특정 요소를 꾸미는 규칙이며, 선택자 범위가 넓거나 우선순위가 복잡하면 한 곳의 변경이 다른 화면까지 영향을 줄 수 있다. `!important`를 계속 추가해 해결하면 원래 규칙의 의도를 파악하기 어려워진다. 가능한 한 컴포넌트 단위로 스타일의 범위를 제한하고, 상태 클래스와 레이아웃 책임을 구분하는 편이 좋다.

Flexbox는 한 축을 중심으로 요소를 배치할 때, Grid는 행과 열을 함께 설계할 때 유용하다. 둘 중 하나를 모든 상황에 쓰기보다 콘텐츠의 흐름과 반응형 요구에 맞춰 선택한다.

### 디버깅 순서
1. 개발자 도구에서 실제 적용된 규칙과 취소된 규칙을 확인한다.
2. 상속, 특이성, 선언 순서 중 무엇이 원인인지 분리한다.
3. 부모 컨테이너의 크기와 overflow를 확인한다.
4. 작은 화면에서 고정 너비·긴 문자열·줄바꿈이 어떻게 동작하는지 테스트한다.

레이아웃 오류는 자식 요소만 수정해서 해결되지 않을 수 있다. 부모의 너비와 정렬 기준부터 확인하면 불필요한 CSS 덧붙이기를 줄일 수 있다.
