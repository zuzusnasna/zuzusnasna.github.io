관계형 데이터베이스에서는 한 테이블에 모든 정보를 넣지 않기 때문에 여러 테이블을 연결해서 조회하는 일이 많다.

## JOIN

```sql
SELECT e.name, d.department_name
FROM employee e
JOIN department d
  ON e.department_id = d.department_id;
```

`JOIN`은 서로 다른 테이블의 관계를 이용해 하나의 결과로 묶는 방식이다.

대표적으로 `INNER JOIN`, `LEFT JOIN`을 구분해서 사용했다.

## 서브쿼리

다른 조회 결과를 조건으로 사용해야 할 때 서브쿼리를 활용할 수 있다.

```sql
SELECT name, salary
FROM employee
WHERE salary > (
    SELECT AVG(salary)
    FROM employee
);
```

## 배운 점

JOIN은 **테이블 사이의 관계**, 서브쿼리는 **조회 결과를 다시 조건으로 사용하는 것**이라고 구분하니 이해하기 쉬웠다.

이후 SQL 튜닝을 공부할 때도 같은 결과를 어떤 JOIN과 조건으로 만들었는지가 성능에 영향을 준다는 점으로 이어졌다.

## 더 깊게 이해하기: JOIN은 관계를 결과 집합으로 표현한다

JOIN을 작성할 때는 먼저 각 테이블의 행이 어떤 의미인지, 조인 키가 유일한지, 결과가 몇 행으로 늘어날 수 있는지 예상해야 한다. 일대다 관계를 조인하면 부모 행 하나가 자식 행 수만큼 반복될 수 있다. 결과가 중복처럼 보인다고 무조건 DISTINCT를 붙이면 데이터 모델이나 조인 조건의 문제를 가릴 수 있다.

서브쿼리는 값 하나, 행 집합, 존재 여부 등 여러 형태로 사용된다. `EXISTS`는 관련 행의 존재를 확인할 때 자연스럽고, `IN`은 값 집합과의 비교에 읽기 쉬울 수 있다. NULL이 포함된 조건은 특히 주의해야 하며, `NOT IN`은 서브쿼리 결과에 NULL이 있으면 기대와 다른 결과를 낼 수 있다.

### 쿼리를 검토하는 질문
- 조인 조건이 누락되어 카티션 곱이 발생하지 않는가?
- 결과의 기준 단위가 고객인지, 주문인지, 주문 항목인지 명확한가?
- NULL과 중복 값이 있을 때도 결과가 의도에 맞는가?
- 복잡한 쿼리를 단계별로 분리해 각 단계의 행 수를 확인했는가?

JOIN은 테이블을 합치는 문법이 아니라 관계의 카디널리티를 이해하고 원하는 결과 단위를 정의하는 작업이다.
