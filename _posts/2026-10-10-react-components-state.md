React Study 저장소에서 실습한 내용을 기준으로 컴포넌트와 상태 관리의 기본을 정리했다.

## Component

화면을 기능 단위로 나누어 재사용할 수 있게 만든다.

```jsx
function Card({ title }) {
  return <div>{title}</div>;
}
```

## Props

부모 컴포넌트가 자식 컴포넌트에 데이터를 전달할 때 사용한다.

## State

화면에서 변경되는 값을 컴포넌트 내부에서 관리한다.

```jsx
const [count, setCount] = useState(0);

<button onClick={() => setCount(count + 1)}>
  {count}
</button>
```

## 배운 점

React에서는 화면을 직접 조작하기보다 **상태가 바뀌면 UI가 다시 계산된다**는 방식으로 생각하는 것이 중요했다.

Vite 프로젝트를 직접 구성하고 컴포넌트를 분리해 보면서 작은 화면부터 상태 기반 UI로 만드는 흐름을 익혔다.

## 더 깊게 이해하기: 컴포넌트 경계는 변경 이유로 나눈다

컴포넌트를 나누는 기준은 파일 길이만이 아니다. 독립적으로 재사용되는 UI, 별도의 상태와 이벤트를 가진 영역, 변경 이유가 다른 영역을 분리하면 테스트와 유지보수가 쉬워진다. 반대로 지나치게 작은 컴포넌트를 만들면 props 전달만 복잡해지고 전체 흐름을 따라가기 어려울 수 있다.

상태를 어디에 둘지 결정할 때는 해당 값이 필요한 컴포넌트들을 확인한다. 한 화면에서만 쓰이는 입력 상태는 해당 컴포넌트에 두고, 여러 영역에서 공유되는 선택 값은 공통 부모나 별도 상태 계층으로 올릴 수 있다.

### 리팩터링 체크리스트
- 컴포넌트의 이름이 역할을 설명하는가?
- UI 표현과 데이터 조회·변환 로직이 지나치게 섞이지 않았는가?
- 동일한 상태를 여러 곳에 복사해 저장하지 않는가?
- props가 너무 깊게 전달된다면 상태 소유권이나 컴포넌트 경계를 재검토했는가?

좋은 컴포넌트 구조는 추상화의 양이 아니라 변경 시 함께 바뀌어야 할 코드가 함께 묶여 있는지로 평가할 수 있다.
