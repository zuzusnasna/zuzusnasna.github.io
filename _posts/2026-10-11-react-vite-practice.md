React Study에서 Vite 기반 프로젝트를 만들고 컴포넌트를 분리하는 실습을 진행했다.

## 기본 흐름

```text
main.jsx
   ↓
App.jsx
   ↓
Component
   ↓
화면 렌더링
```

Vite는 개발 서버와 빌드 환경을 빠르게 구성할 수 있어 React 실습 프로젝트를 시작하기 편했다.

## 실습하면서 확인한 부분

- `package.json`의 의존성 관리
- `main.jsx`에서 React 진입점 확인
- `App.jsx`에서 화면 구성
- 컴포넌트 파일 분리
- CSS 파일 분리
- `npm run dev`와 `npm run build` 차이

## 배운 점

프레임워크를 사용하는 것보다 **프로젝트의 진입점과 빌드 과정을 직접 확인하는 것**이 이후 오류를 해결할 때 도움이 됐다.

## 더 깊게 이해하기: 개발 환경을 재현 가능하게 만들기

프론트엔드 프로젝트도 의존성 버전과 실행 명령이 개발자마다 달라지면 같은 코드를 재현하기 어렵다. `package.json`은 실행 스크립트와 의존성을 정의하고, lock 파일은 실제 설치된 의존성 트리를 고정하는 역할을 한다. lock 파일이 있는 프로젝트라면 `npm ci`를 사용해 정의된 의존성 상태를 재현하는 편이 적합하다.

Vite 개발 서버에서 API를 프록시하는 설정은 브라우저의 개발 편의를 위한 것이다. 운영 배포에서는 프록시를 제공하는 서버와 API 경로가 실제로 일치하는지 확인해야 한다. 로컬에서는 되는 기능이 배포에서 실패하면 코드뿐 아니라 base 경로, 프록시, 정적 파일 위치를 확인해야 한다.

### 실습 점검
- 새로 클론한 디렉터리에서 문서에 적힌 명령만으로 실행할 수 있는가?
- lock 파일과 Node 버전이 팀에서 공유되는가?
- 환경변수를 코드에 하드코딩하지 않고 예시 파일로 안내하는가?
- 개발 서버와 운영 서버의 API 라우팅 차이를 알고 있는가?

환경 설정은 부수적인 작업이 아니라 팀원이 같은 결과를 재현하기 위한 프로젝트 구성의 일부다.
