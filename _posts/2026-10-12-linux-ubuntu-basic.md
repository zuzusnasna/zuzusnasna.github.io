EC2 서버를 다루면서 Linux 명령어는 개발 환경을 확인하는 도구라는 느낌으로 익히게 됐다.

## 프로세스와 자원 확인

```bash
top
free -h
df -h
ps aux
```

특히 `free -h`로 메모리와 swap을 확인하고 `top`으로 CPU와 I/O 상태를 확인하면 서버가 느려졌을 때 원인을 좁힐 수 있다.

## 파일과 로그 확인

```bash
ls -al
cd ~/RealTimeChat
tail -f app.log
```

## 배운 점

서버 문제를 만났을 때 바로 애플리케이션 코드를 수정하기보다 **CPU, 메모리, swap, 디스크, 프로세스 상태부터 확인하는 습관**을 만들었다.

## 더 깊게 이해하기: 리눅스에서는 프로세스와 서비스의 상태를 구분한다

명령어를 실행하는 것과 백그라운드 서비스가 정상 운영되는 것은 다르다. 프로세스가 존재해도 포트를 열지 못했거나, 외부 요청을 처리하지 못하거나, 의존 서비스에 연결하지 못할 수 있다. 따라서 프로세스 목록만으로 상태를 판단하지 않고 로그, 포트, 헬스 체크를 함께 확인해야 한다.

파일 권한은 소유자·그룹·기타 사용자에 대한 읽기·쓰기·실행 권한으로 나뉜다. 편의를 위해 모든 파일에 `chmod 777`을 적용하면 필요한 범위보다 과도한 권한을 부여하게 된다. 서비스 계정이 꼭 필요한 파일과 명령에만 접근하도록 권한을 최소화해야 한다.

### 서버 점검 순서
- 서비스 상태와 최근 로그를 확인한다.
- 실제 리슨 포트와 프로세스의 PID를 연결해 본다.
- 설정 파일과 환경변수의 권한 및 소유자를 확인한다.
- 디스크, 메모리, CPU 사용량을 확인한 뒤 애플리케이션 로그와 대조한다.

리눅스 명령어를 외우는 것보다 어떤 질문에 답하기 위해 어떤 명령을 실행하는지 익히는 것이 운영 문제를 해결하는 데 도움이 된다.
