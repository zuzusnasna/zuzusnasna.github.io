PL/SQL에서는 SQL을 실행하는 것뿐 아니라 조건문, 반복문, 예외 처리를 이용해 DB 안에서 업무 로직을 처리할 수 있다.

## 기본 구조

```sql
DECLARE
    v_count NUMBER;
BEGIN
    SELECT COUNT(*) INTO v_count FROM employee;
    DBMS_OUTPUT.PUT_LINE(v_count);
EXCEPTION
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE(SQLERRM);
END;
/
```

`DECLARE → BEGIN → EXCEPTION` 구조를 기준으로 생각하면 블록의 역할을 나누기 쉽다.

## 예외 처리

예외가 발생했을 때 아무 처리 없이 종료시키기보다 예상 가능한 오류를 명확하게 처리한다.

```sql
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('조회 결과가 없습니다.');
```

## 프로시저 설계

프로시저는 반복해서 실행할 DB 업무를 하나의 단위로 묶을 때 유용하다. 매개변수를 받아 데이터를 변경하거나 조회하는 업무를 재사용할 수 있다.

## 배운 점

PL/SQL은 단순 SQL보다 **데이터를 처리하는 업무 흐름 자체를 DB 안에 표현할 수 있는 언어**라는 점이 핵심이었다.

## 더 깊게 이해하기: 예외 처리에는 복구 정책이 필요하다

PL/SQL 예외는 실행 중 발생한 오류를 감지하고 처리 흐름을 제어하는 수단이다. `WHEN OTHERS`로 모든 예외를 잡을 수는 있지만, 무조건 성공처럼 처리하거나 오류 정보를 버리면 데이터가 잘못된 상태로 남을 수 있다. 예상 가능한 오류는 구체적으로 처리하고, 예상하지 못한 오류는 원인을 기록한 뒤 적절히 다시 발생시키는 편이 안전하다.

예외가 발생했을 때 트랜잭션 전체를 취소할지, 특정 행만 실패로 기록하고 나머지를 계속 처리할지는 업무 요구사항에 따라 달라진다. 특히 정산이나 급여처럼 일부 데이터만 반영되면 안 되는 업무에서는 원자성이 중요하다.

### 점검 항목
- 예상 가능한 예외와 시스템 오류를 구분했는가?
- 오류 메시지와 발생 지점을 추적할 수 있는가?
- 예외를 처리한 뒤 데이터가 부분 반영된 상태로 남지 않는가?
- 재실행할 때 같은 오류가 반복되거나 중복 반영되지 않는가?

예외 처리는 오류를 감추는 기술이 아니라 실패했을 때 시스템이 어떤 상태를 유지해야 하는지 정의하는 작업이다.
