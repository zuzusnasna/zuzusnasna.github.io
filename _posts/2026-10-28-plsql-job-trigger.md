PL/SQL을 공부하면서 프로시저, JOB, TRIGGER가 각각 어떤 역할을 하는지 정리했다.

## 1. 프로시저

프로시저는 특정 작업을 하나의 단위로 묶어 필요할 때 호출하는 데 사용한다.

예를 들어 회원의 등급을 갱신하거나 여러 테이블을 함께 수정해야 하는 작업을 하나의 프로시저로 만들 수 있다.

## 2. JOB

JOB은 정해진 시간이나 주기에 맞춰 작업을 자동으로 실행한다.

```text
매일 00:00
    ↓
JOB 실행
    ↓
회원 등급 갱신 프로시저 호출
```

사용자가 직접 요청하지 않아도 정기적으로 처리해야 하는 작업에 적합하다.

## 3. TRIGGER

TRIGGER는 특정 테이블에서 INSERT, UPDATE, DELETE 같은 이벤트가 발생했을 때 자동으로 실행된다.

예를 들어 배터리 잔량이 변경되면 변경 이력을 기록하는 TRIGGER를 만들 수 있다.

```text
배터리 UPDATE
    ↓
TRIGGER 자동 실행
    ↓
변경 이력 저장
```

## 4. JOB과 TRIGGER의 차이

JOB은 **시간을 기준으로 실행**되고, TRIGGER는 **데이터 변경 이벤트를 기준으로 실행**된다는 차이가 핵심이다.

- 정해진 시간마다 실행 → JOB
- 데이터 변경 즉시 실행 → TRIGGER
- 여러 SQL 작업을 호출 가능한 단위로 묶음 → PROCEDURE

## 5. 정리

세 기능은 서로 대체하는 관계가 아니라 실행 조건이 다르다.

실제 시스템에서는 프로시저를 작업 단위로 만들고, JOB이 주기적으로 프로시저를 실행하거나 TRIGGER가 데이터 변경 시 필요한 처리를 수행하는 형태로 조합할 수 있다.

## 더 깊게 이해하기: 자동 실행은 실패까지 추적할 수 있어야 한다

Job과 Trigger는 사용자가 직접 실행하지 않아도 동작하기 때문에 실행 경로가 눈에 잘 보이지 않는다. 실행 조건, 주기, 대상 데이터, 실패 처리, 재실행 방법을 문서화해야 한다. Job이 이전 실행을 끝내기 전에 다시 시작되면 중복 처리나 잠금 경합이 생길 수 있다.

Trigger는 데이터 변경 트랜잭션 안에서 실행되는 경우가 많으므로 Trigger 내부 오류가 원래 DML에 미치는 영향을 확인해야 한다. 외부 시스템 호출이나 지나치게 많은 업무 로직을 Trigger에 넣으면 응답 시간이 길어지고 실패 원인을 찾기 어려워질 수 있다.

### 운영 점검표
- 마지막 실행 결과와 처리 건수를 확인할 수 있는가?
- 중복 실행 방지와 실패 후 재처리 정책이 있는가?
- Trigger가 실제 필요한 변경에서만 실행되는가?
- 실행 시간과 실패 원인을 남겨 이상 징후를 찾을 수 있는가?

자동화는 반복 작업을 없애는 것뿐 아니라 실패를 관측하고 복구할 수 있게 만드는 일이다.
