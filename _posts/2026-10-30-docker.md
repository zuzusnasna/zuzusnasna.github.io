---# Docker (도커)

## 1. Docker란?

Docker는 애플리케이션을 실행하는 데 필요한 환경과 라이브러리, 설정 등을 하나로 묶어 **컨테이너(Container)라는 독립적인 실행 환경으로 만들어 주는 플랫폼**이다.

개발 환경과 실제 서버 환경이 달라서 발생하는 문제를 줄이고, 동일한 환경에서 애플리케이션을 실행할 수 있도록 도와준다.

### Docker를 사용하는 이유

기존에는 개발자마다 설치된 프로그램이나 버전이 다를 수 있었다.

예를 들어,
- 개발자 A : Java 21, MySQL 8.0
- 개발자 B : Java 17, MySQL 8.4
- 서버 : Java 21, MySQL 8.4

이처럼 실행 환경이 다르면 로컬에서는 정상적으로 동작하지만 서버에서는 오류가 발생할 수 있다.

Docker를 사용하면 실행에 필요한 환경을 이미지로 구성하여 동일한 설정을 여러 환경에서 사용할 수 있다.

```text
기존 방식

개발자 PC                서버
Java 설치                Java 설치
MySQL 설치               MySQL 설치
Redis 설치               Redis 설치
환경별 설정 관리          환경별 설정 관리

             ↓

Docker 방식

       Docker Image
             ↓
    동일한 실행 환경 구성
       ↙          ↘
   개발자 PC       서버
   Container     Container
```

## 2. Docker의 주요 개념

### 2-1. Image (이미지)

컨테이너를 생성하기 위한 실행 환경의 설계도이다.

애플리케이션 실행에 필요한 파일, 라이브러리, 설정 등을 포함한다.

예시:
- MySQL 이미지
- Redis 이미지
- Ubuntu 이미지
- Spring Boot 애플리케이션 이미지

```bash
docker pull mysql:8.4
```

MySQL 8.4 이미지를 다운로드한다.

### 2-2. Container (컨테이너)

이미지를 기반으로 생성되어 실제로 실행되는 독립적인 환경이다.

하나의 이미지로 여러 컨테이너를 생성할 수 있다.

```text
          MySQL Image
               |
       ┌───────┴───────┐
       ↓               ↓
  Container A     Container B
  MySQL 실행        MySQL 실행
```

### 2-3. Dockerfile

Docker 이미지를 만들기 위한 명령어를 작성하는 파일이다.

애플리케이션을 어떤 환경에서 어떻게 실행할지 정의한다.

```dockerfile
FROM eclipse-temurin:21-jre

WORKDIR /app

COPY build/libs/*.jar app.jar

ENTRYPOINT ["java", "-jar", "app.jar"]
```

- `FROM` : 기반 이미지 지정
- `WORKDIR` : 작업 디렉터리 지정
- `COPY` : 파일 복사
- `ENTRYPOINT` : 컨테이너 실행 시 수행할 명령어

### 2-4. Docker Compose

여러 컨테이너를 하나의 설정 파일로 관리하는 도구이다.

Spring Boot, MySQL, Redis처럼 여러 서비스를 함께 실행할 때 사용한다.

`compose.yaml` 파일에 각 서비스의 이미지, 포트, 환경변수, 볼륨 등을 정의한다.

```text
          Docker Compose
                 |
       ┌─────────┼─────────┐
       ↓         ↓         ↓
   Spring Boot  MySQL     Redis
   Container   Container Container
       └─────────┼─────────┘
                 ↓
           하나의 명령어로
            전체 실행
```

```bash
docker compose up -d
```

## 3. Docker의 장점

### 3-1. 환경 통일

개발자 PC와 서버에서 동일한 이미지를 사용하여 실행 환경 차이로 발생하는 문제를 줄일 수 있다.

### 3-2. 쉬운 배포

서버에 Java, MySQL, Redis 등을 일일이 설치하고 설정할 필요 없이 이미지와 설정 파일을 이용하여 실행할 수 있다.

### 3-3. 빠른 실행과 확장

필요한 컨테이너를 빠르게 생성하고 제거할 수 있다.

동일한 애플리케이션 컨테이너를 여러 개 실행하는 것도 가능하다.

### 3-4. 자원 효율성

가상 머신처럼 각각 별도의 운영체제를 실행하는 방식이 아니라 호스트 운영체제의 커널을 공유하는 컨테이너 방식이므로 일반적으로 가상 머신보다 가볍다.

### 3-5. 격리된 실행 환경

컨테이너마다 실행 환경과 프로세스, 네트워크 등을 분리하여 관리할 수 있다.

## 4. Docker와 가상 머신(VM)의 차이

| 구분 | Docker Container | 가상 머신(VM) |
|---|---|---|
| 실행 방식 | 호스트 커널 공유 | 별도 OS 실행 |
| 운영체제 | 별도 OS 전체 설치 불필요 | 게스트 OS 필요 |
| 자원 사용 | 상대적으로 적음 | 상대적으로 많음 |
| 실행 속도 | 일반적으로 빠름 | 상대적으로 느림 |
| 격리 수준 | 프로세스 및 시스템 자원 격리 | 별도 OS 기반 격리 |
| 활용 | 애플리케이션 배포 및 실행 | OS 단위 환경 구성 |

```text
가상 머신 구조

       Host OS
           |
       Hypervisor
       /        \
      VM         VM
   Guest OS   Guest OS
   App        App

Docker 구조

       Host OS
           |
     Docker Engine
      /    |    \
 Container Container Container
    App       DB      Redis
```

Docker는 운영체제 전체를 실행하는 것이 아니라 애플리케이션 실행에 필요한 환경을 컨테이너 단위로 관리한다.

# 5. Docker 다운로드 및 설치 (Windows)

Windows에서는 Docker Desktop을 설치하는 방법이 가장 간단하다.

Docker Desktop에는 Docker Engine, Docker CLI, Docker Compose 등이 포함되어 있다.

### 5-1. 설치 전 확인

필요한 환경:
- Windows 10/11 지원 버전
- 64비트 CPU
- BIOS/UEFI 가상화 활성화
- WSL 2 사용을 위한 시스템 요구사항 충족

### 5-2. WSL 2 설치

WSL(Windows Subsystem for Linux)은 Windows에서 Linux 환경을 사용할 수 있도록 지원하는 기능이다.

Docker Desktop은 WSL 2를 기반으로 Linux 컨테이너를 실행할 수 있다.

PowerShell을 관리자 권한으로 실행한다.

```powershell
wsl --install
```

설치 후 필요하면 컴퓨터를 재부팅한다.

WSL 버전 확인:

```powershell
wsl --version
```

WSL 업데이트:

```powershell
wsl --update
```

### 5-3. Docker Desktop 다운로드

공식 다운로드 페이지:

https://www.docker.com/products/docker-desktop/

설치 순서:

1. Docker Desktop 다운로드
2. 설치 파일 실행
3. WSL 2 기반 설치 옵션 선택
4. 설치 완료 후 Docker Desktop 실행
5. 약관 동의
6. Docker Engine이 정상적으로 시작되는지 확인

### 5-4. Docker 설정

Docker Desktop 실행 후 다음 항목을 확인한다.

**Settings → General**
- Use the WSL 2 based engine 활성화

**Settings → Resources → WSL Integration**
- 사용하는 Linux 배포판의 Docker 통합 활성화

**Settings → Resources → Advanced**
- CPU 및 메모리 사용량 확인
- 필요에 따라 자원 제한 설정

### 5-5. 설치 확인

PowerShell 또는 터미널에서 다음 명령어를 실행한다.

```bash
docker --version
```

Docker Compose 버전 확인:

```bash
docker compose version
```

Docker Engine 정상 작동 확인:

```bash
docker info
```

테스트 컨테이너 실행:

```bash
docker run hello-world
```

정상적으로 실행되면 Docker 설치가 완료된 것이다.

# 6. Docker 기본 사용법

## 6-1. 이미지 다운로드

```bash
docker pull mysql:8.4
```

Docker Hub에서 MySQL 8.4 이미지를 다운로드한다.

## 6-2. 이미지 목록 확인

```bash
docker images
```

현재 로컬에 저장된 이미지 목록을 확인한다.

## 6-3. 컨테이너 실행

```bash
docker run -d \
  --name my-mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=1234 \
  mysql:8.4
```

옵션 설명:

| 옵션 | 의미 |
|---|---|
| `-d` | 백그라운드 실행 |
| `--name` | 컨테이너 이름 지정 |
| `-p` | 호스트 포트와 컨테이너 포트 연결 |
| `-e` | 환경변수 설정 |

## 6-4. 컨테이너 목록 확인

```bash
docker ps
```

현재 실행 중인 컨테이너 확인

```bash
docker ps -a
```

종료된 컨테이너까지 전체 확인

## 6-5. 컨테이너 중지 및 시작

```bash
docker stop my-mysql
```

```bash
docker start my-mysql
```

## 6-6. 컨테이너 삭제

```bash
docker rm my-mysql
```

컨테이너를 삭제한다.

## 6-7. 이미지 삭제

```bash
docker rmi mysql:8.4
```

사용하지 않는 이미지를 삭제한다.

## 6-8. 로그 확인

```bash
docker logs my-mysql
```

실시간 로그 확인:

```bash
docker logs -f my-mysql
```

# 7. Docker Compose 실습

Spring Boot 프로젝트를 개발할 때 MySQL과 Redis를 Docker로 실행하는 예시이다.

### 7-1. compose.yaml 생성

프로젝트 최상위 경로에 `compose.yaml` 파일을 생성한다.

```yaml
services:
  mysql:
    image: mysql:8.4
    container_name: local-mysql
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASSWORD}
      MYSQL_DATABASE: testdb
    ports:
      - "3307:3306"
    volumes:
      - mysql-data:/var/lib/mysql

  redis:
    image: redis:7
    container_name: local-redis
    ports:
      - "6379:6379"

volumes:
  mysql-data:
```

### 7-2. .env 파일 생성

```env
DB_PASSWORD=1234
```

실제 비밀번호가 포함된 `.env`는 Git에 올리지 않는다.

`.gitignore`에 추가한다.

```gitignore
.env
```

팀원에게는 `.env.example`을 제공하여 필요한 환경변수를 안내한다.

### 7-3. 컨테이너 실행

```bash
docker compose up -d
```

설정 파일에 정의한 MySQL과 Redis가 실행된다.

### 7-4. 실행 상태 확인

```bash
docker compose ps
```

### 7-5. 로그 확인

```bash
docker compose logs -f
```

특정 서비스 로그 확인:

```bash
docker compose logs -f mysql
```

### 7-6. 컨테이너 중지

```bash
docker compose stop
```

### 7-7. 컨테이너 제거

```bash
docker compose down
```

컨테이너와 Compose 네트워크를 제거한다.

**주의:** `docker compose down -v`를 실행하면 Compose가 관리하는 볼륨도 제거되므로 데이터베이스 데이터가 삭제될 수 있다.

# 8. Docker에서 데이터 관리하기 (Volume)

컨테이너는 삭제되거나 재생성될 수 있기 때문에 데이터베이스처럼 중요한 데이터는 별도로 보존해야 한다.

이때 사용하는 것이 Volume이다.

### Volume이란?

컨테이너 외부에 데이터를 저장하여 컨테이너가 삭제되어도 데이터를 유지할 수 있도록 하는 기능이다.

```text
       MySQL Container
              |
              ↓
          Volume
              |
       데이터 영구 보관
```

예를 들어 MySQL 컨테이너를 삭제하더라도 Volume을 유지하면 데이터베이스 데이터를 보존할 수 있다.

Volume 목록 확인:

```bash
docker volume ls
```

Volume 상세 확인:

```bash
docker volume inspect mysql-data
```

Volume 삭제:

```bash
docker volume rm mysql-data
```

**중요:** 컨테이너와 Volume은 별개이다. 컨테이너를 삭제했다고 Volume까지 자동으로 삭제되는 것은 아니다.

# 9. Docker Network

컨테이너끼리 통신하기 위해 사용하는 네트워크이다.

예를 들어 Spring Boot 컨테이너가 MySQL 컨테이너에 접근하려면 네트워크를 통해 연결해야 한다.

```text
       Docker Network
              |
       ┌──────┴──────┐
       ↓             ↓
  Spring Boot      MySQL
  Container       Container
       |
       └── DB 연결
```

같은 Docker 네트워크에 연결된 컨테이너는 일반적으로 컨테이너 이름을 이용해 통신할 수 있다.

예를 들어 Spring Boot가 MySQL에 접속할 때:

```properties
spring.datasource.url=jdbc:mysql://mysql:3306/testdb
```

여기서 `mysql`은 Compose에 정의한 서비스 이름이다.

주의할 점은 다음과 같다.

- 로컬 PC에서 실행하는 Spring Boot → `localhost:3307`
- Docker 컨테이너에서 실행하는 Spring Boot → `mysql:3306`

호스트 포트와 컨테이너 내부 포트를 구분해야 한다.

# 10. Docker 사용 시 주의사항

### 10-1. 포트 충돌

이미 로컬에서 MySQL이 3306 포트를 사용하고 있다면 Docker에서도 같은 호스트 포트를 사용할 때 충돌이 발생할 수 있다.

```yaml
ports:
  - "3307:3306"
```

이렇게 설정하면 호스트의 3307 포트를 컨테이너의 3306 포트에 연결할 수 있다.

### 10-2. 데이터 삭제 주의

```bash
docker compose down -v
```

`-v` 옵션은 볼륨까지 삭제하므로 DB 데이터를 잃을 수 있다.

데이터가 필요한 경우 실행 전에 반드시 확인한다.

### 10-3. 환경변수 및 비밀번호 관리

DB 비밀번호, API Key 등 민감한 정보는 Dockerfile이나 Git 저장소에 직접 작성하지 않는다.

`.env`, 환경변수, 비밀정보 관리 기능 등을 사용한다.

### 10-4. 자원 사용량 관리

Docker도 CPU, 메모리, 디스크 등의 자원을 사용한다.

특히 여러 개의 컨테이너를 동시에 실행하면 PC 성능에 영향을 줄 수 있다.

### 10-5. 이미지 버전 관리

```yaml
image: mysql:latest
```

`latest`를 사용하면 나중에 이미지를 다시 내려받을 때 버전이 달라질 수 있다.

가능하면 명확한 버전을 지정한다.

```yaml
image: mysql:8.4
```

### 10-6. 컨테이너와 이미지 구분

- 컨테이너를 삭제해도 이미지가 자동으로 삭제되는 것은 아니다.
- 이미지를 삭제하려면 해당 이미지를 사용하는 컨테이너가 없어야 한다.
- 컨테이너를 삭제해도 외부 Volume은 남아 있을 수 있다.

# 11. Docker를 실제 프로젝트에서 사용하는 흐름

Spring Boot 기반 백엔드 프로젝트를 개발한다고 가정한다.

### 개발 환경

```text
개발자 PC
   |
   └── Spring Boot 실행
          |
          ├── MySQL Container
          |
          └── Redis Container
```

개발자는 Docker로 MySQL과 Redis를 실행하고 Spring Boot는 로컬에서 실행할 수 있다.

이렇게 하면 DB와 캐시 서버를 직접 설치하지 않아도 된다.

### 배포 환경

```text
             EC2 서버
                |
             Docker
                |
       ┌────────┼────────┐
       ↓        ↓        ↓
   Spring Boot  MySQL    Redis
   Container   Container Container
       |
       ↓
     Nginx
       |
       ↓
     사용자
```

배포 서버에서도 Docker 이미지를 기반으로 컨테이너를 실행한다.

개발 환경과 배포 환경의 차이를 줄이고 여러 서비스를 일관된 방식으로 관리할 수 있다.

| Container | 이미지를 기반으로 실행되는 독립적인 환경 |
| Dockerfile | 이미지를 생성하기 위한 명령어 파일 |
| Docker Compose | 여러 컨테이너를 하나의 설정으로 관리 |
| Volume | 컨테이너 외부에 데이터를 영구적으로 저장 |
| Network | 컨테이너 간 통신을 위한 네트워크 |
| Docker Hub | Docker 이미지를 저장하고 공유하는 레지스트리 |

## 핵심 명령어 모음

| 명령어 | 기능 |
|---|---|
| `docker --version` | Docker 버전 확인 |
| `docker pull` | 이미지 다운로드 |
| `docker images` | 이미지 목록 확인 |
| `docker run` | 컨테이너 생성 및 실행 |
| `docker ps` | 실행 중인 컨테이너 확인 |
| `docker ps -a` | 전체 컨테이너 확인 |
| `docker stop` | 컨테이너 중지 |
| `docker start` | 컨테이너 시작 |
| `docker rm` | 컨테이너 삭제 |
| `docker rmi` | 이미지 삭제 |
| `docker logs` | 컨테이너 로그 확인 |
| `docker compose up -d` | Compose 서비스 실행 |
| `docker compose down` | Compose 컨테이너 및 네트워크 제거 |
| `docker volume ls` | Volume 목록 확인 |

## 오늘의 핵심 정리

1. Docker는 개발 및 배포 환경을 컨테이너 단위로 구성하여 환경 차이를 줄이는 기술이다.
2. Image는 컨테이너를 만들기 위한 설계도이고 Container는 실제 실행 환경이다.
3. Dockerfile은 이미지 생성 방법을 정의하고 Docker Compose는 여러 컨테이너를 함께 관리한다.
4. Volume을 사용하면 컨테이너가 삭제되더라도 데이터를 유지할 수 있다.
5. Network를 사용하면 여러 컨테이너가 서로 통신할 수 있다.
6. Docker를 사용하면 Spring Boot, MySQL, Redis 등의 실행 환경을 통일하고 배포 과정을 단순화할 수 있다.

### 한 줄 정리

> Docker는 애플리케이션 실행에 필요한 환경을 이미지로 만들고, 이를 컨테이너로 실행하여 개발 환경부터 배포 환경까지 일관성 있게 관리할 수 있도록 해주는 기술이다.
