## 1. Garbage Collection이란?

Java는 객체 메모리를 개발자가 직접 해제하기보다 JVM의 Garbage Collector(GC)가 관리한다. GC는 더 이상 프로그램에서 도달할 수 없는 객체를 찾아 메모리를 회수한다.

GC가 있다고 메모리 관리가 완전히 자동으로 해결되는 것은 아니다. 불필요한 참조를 계속 유지하면 객체는 살아 있는 상태로 남아 메모리 누수가 발생할 수 있다.

## 2. Heap과 객체 생성

일반적인 객체와 배열은 Heap 영역에 생성된다.

```java
Member member = new Member("Kim");
```

new로 생성한 객체는 Heap에 만들어지고, 지역 변수 member는 객체를 참조한다. 지역 변수 자체와 객체가 저장되는 위치는 구분해서 이해해야 한다.

## 3. 객체 도달 가능성

GC는 객체가 null인지 여부만 확인하지 않는다. GC Roots에서 객체까지 참조 경로가 이어지는지 확인한다.

대표적인 GC Roots에는 실행 중인 스레드의 스택 참조, static 필드, JNI 참조 등이 있다. 루트에서 도달할 수 없는 객체는 회수 후보가 된다.

객체 A와 B가 서로 참조하더라도 두 객체 모두 루트에서 도달할 수 없다면 회수될 수 있다.

## 4. Generational Hypothesis와 세대별 영역

많은 GC는 객체의 생존 기간이 서로 다르다는 특성을 활용한다. 대부분의 객체는 짧은 시간 사용된 뒤 사라지고, 오래 살아남은 객체는 계속 유지될 가능성이 높다는 가정이다.

HotSpot JVM의 대표적인 세대별 GC 구조는 다음과 같이 이해할 수 있다.

```text
Heap
 ├─ Young Generation
 │   ├─ Eden
 │   ├─ Survivor 0
 │   └─ Survivor 1
 └─ Old Generation
```

새 객체는 일반적으로 Eden에서 할당된다. Young 영역에서 살아남은 객체는 Survivor 영역을 거치며, 생존 횟수나 정책에 따라 Old 영역으로 이동할 수 있다. 실제 배치와 정책은 GC 종류와 JVM 버전에 따라 달라진다.

## 5. Minor GC와 Major/Full GC

Young 영역에서 주로 발생하는 수집을 Minor GC라고 부른다. Old 영역까지 포함한 수집은 Major 또는 Full GC 등으로 표현되지만, 용어와 범위는 GC 구현과 문맥에 따라 다를 수 있다.

Full GC는 넓은 영역을 대상으로 하기 때문에 애플리케이션 정지 시간이 길어질 수 있다. 다만 모든 GC가 항상 애플리케이션 전체를 같은 방식으로 멈추는 것은 아니다. 수집기별로 동작 방식이 다르다.

## 6. 대표적인 GC 알고리즘

### Mark-Sweep

1. 살아 있는 객체를 표시(Mark)한다.
2. 표시되지 않은 객체의 메모리를 회수(Sweep)한다.

구현이 단순하지만 빈 공간이 여러 조각으로 나뉘는 단편화가 발생할 수 있다.

### Mark-Compact

살아 있는 객체를 표시한 다음 한쪽으로 모아 연속된 공간을 확보한다. 단편화를 줄일 수 있지만 객체 이동 비용이 발생한다.

### Copying

한 영역에서 살아남은 객체를 다른 영역으로 복사하고 기존 영역을 비운다. 살아 있는 객체가 적은 영역을 수집할 때 효율적일 수 있다. Young Generation의 Survivor 처리 개념과 연결해 이해할 수 있다.

## 7. GC 종류

HotSpot JVM에는 여러 수집기가 있다.

| GC | 특징 |
| --- | --- |
| Serial GC | 단일 스레드 중심의 단순한 수집기 |
| Parallel GC | 처리량(Throughput)을 중시 |
| G1 GC | 힙을 여러 Region으로 나눠 관리 |
| ZGC | 낮은 지연 시간을 목표로 설계 |

어떤 GC가 가장 좋은지는 서비스의 힙 크기, 응답 지연 목표, 처리량, CPU·메모리 자원에 따라 달라진다.

## 8. GC가 성능에 미치는 영향

객체가 빠르게 생성되면 GC가 더 자주 동작할 수 있다. GC 중 애플리케이션 스레드가 멈추는 구간을 Stop-The-World(STW)라고 한다. 수집기와 단계에 따라 동시 수행 작업도 있지만 일부 단계에서는 정지가 발생할 수 있다.

성능을 확인할 때는 다음을 살펴본다.

- GC 발생 횟수와 소요 시간
- GC 이후 Heap 사용량
- 객체 할당률
- Old 영역 사용량 추세
- 애플리케이션 응답 시간과 GC 정지 시간

## 9. System.gc() 주의

System.gc()는 GC 수행을 요청하는 힌트다. 즉시 실행이나 메모리 회수를 보장하지 않는다. 일반적인 서버 코드에서 반복 호출해 메모리를 관리하려는 방식은 피해야 한다.

## 핵심 정리

- 객체는 일반적으로 Heap에 생성된다.
- GC는 GC Roots에서의 도달 가능성을 기준으로 객체를 판단한다.
- 세대별 GC는 짧게 살아남는 객체가 많다는 특성을 활용한다.
- Mark-Sweep, Mark-Compact, Copying은 대표적인 회수 알고리즘이다.
- GC 종류는 응답 지연과 처리량 목표에 맞춰 선택한다.
