## 1. NIO란?

NIO(New I/O)는 기존 스트림 중심 I/O를 보완하는 Java의 입출력 API다. Path와 Files를 이용한 파일 관리, Buffer와 Channel 기반 데이터 처리, Selector를 이용한 다중 채널 처리 기능 등을 제공한다.

NIO가 모든 상황에서 기존 I/O보다 빠르다는 뜻은 아니다. 작업의 종류와 데이터 크기, 구현 방식에 따라 적합한 API를 선택해야 한다.

## 2. Path와 Files

Path는 파일 또는 디렉터리의 경로를 표현하고, Files는 파일 생성·복사·이동·삭제와 읽기·쓰기 기능을 제공한다.

```java
Path source = Path.of("data.txt");
Path target = Path.of("backup", "data.txt");

Files.createDirectories(target.getParent());
Files.copy(source, target, StandardCopyOption.REPLACE_EXISTING);

String content = Files.readString(source, StandardCharsets.UTF_8);
```

간단한 파일 작업은 Files API로 읽기 쉽고 간결하게 작성할 수 있다.

## 3. Channel과 Buffer

Channel은 데이터가 오가는 통로이고 Buffer는 읽거나 쓸 데이터를 담는 공간이다. FileChannel은 파일의 특정 위치를 읽거나 쓰는 등 세밀한 파일 처리를 지원한다.

```java
try (FileChannel channel = FileChannel.open(
        Path.of("data.txt"), StandardOpenOption.READ)) {
    ByteBuffer buffer = ByteBuffer.allocate(1024);

    while (channel.read(buffer) != -1) {
        buffer.flip();

        while (buffer.hasRemaining()) {
            System.out.print((char) buffer.get());
        }

        buffer.clear();
    }
}
```

Buffer는 데이터를 채우는 동안 write 모드, 읽을 때는 flip()으로 read 모드로 전환한다. 읽기를 마친 뒤 clear()로 다음 데이터를 받을 준비를 한다.

## 4. Selector와 논블로킹 I/O

Selector는 여러 SelectableChannel의 I/O 이벤트를 한 곳에서 확인할 수 있도록 한다. 논블로킹 채널과 함께 사용하면 하나의 스레드가 여러 연결의 준비 상태를 관리하는 구조를 만들 수 있다.

이 방식은 많은 연결을 효율적으로 다뤄야 하는 네트워크 서버에서 활용될 수 있지만, 직접 구현하려면 이벤트 루프와 버퍼 상태 등을 세심하게 관리해야 한다.

## 5. 기존 I/O와 NIO 선택

- 간단한 텍스트 파일 읽기·쓰기: Files와 Reader/Writer가 편리하다.
- 대용량 파일의 세밀한 위치 기반 처리: FileChannel을 검토한다.
- 다수 네트워크 연결을 논블로킹으로 처리: Selector와 SocketChannel을 검토한다.

NIO라는 이름만으로 선택하기보다 요구사항과 코드 복잡도, 실제 성능 측정 결과를 기준으로 결정한다.
