EC2에서 애플리케이션을 실행하면서 포트가 이미 사용 중이거나 이전 프로세스가 남아 있는 문제를 여러 번 경험했다.

## 포트를 확인하는 이유

```bash
sudo ss -lntp
```

특정 포트를 누가 사용하고 있는지 확인하면 애플리케이션 문제와 실행 환경 문제를 구분할 수 있다.

## 프로세스 확인

```bash
ps aux | grep java
```

컨테이너 안의 프로세스와 호스트에서 직접 실행한 Java 프로세스가 섞이면 어떤 프로세스가 포트를 점유했는지 헷갈릴 수 있다.

## Docker와 함께 볼 것

```text
호스트 포트
   ↓
Docker port mapping
   ↓
컨테이너 내부 포트
   ↓
Spring Boot
```

호스트의 8080과 컨테이너 내부 8080은 같은 개념이 아니다.

## 배운 점

배포 장애가 발생했을 때 애플리케이션 로그만 보는 것보다 **포트 → 프로세스 → 컨테이너 → 애플리케이션 순서로 범위를 좁혀가는 방식**이 문제 해결에 효과적이었다.
