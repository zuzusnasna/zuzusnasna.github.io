사용자가 결제 버튼을 빠르게 두 번 누르거나 네트워크 재시도로 같은 요청이 반복되면 서버는 같은 작업을 두 번 처리할 수 있다.

## 멱등성

같은 요청을 여러 번 보내더라도 결과가 한 번 처리한 것과 동일하도록 만드는 성질이다.

```text
Client
 ↓ POST + Idempotency-Key
Server
 ↓
키가 이미 처리됨?
 ├─ Yes → 기존 결과 반환
 └─ No  → 작업 처리 + 결과 저장
```

## 왜 중요한가

결제, 좌석 예약, 주문 생성처럼 중복 처리가 치명적인 API에서는 단순히 버튼을 비활성화하는 것만으로 충분하지 않다. 클라이언트 재시도와 서버 중복 요청까지 고려해야 한다.

## 구현 시 고려할 것

- 요청을 식별할 고유 키
- 키 저장 위치
- 처리 중인 요청의 동시 접근
- 성공 결과 재사용
- 키의 만료 시간

## 배운 점

동시성 문제는 동시에 여러 사용자가 접근하는 경우뿐 아니라 **같은 사용자의 동일 요청이 반복되는 상황**에서도 발생한다는 것을 알게 됐다.
