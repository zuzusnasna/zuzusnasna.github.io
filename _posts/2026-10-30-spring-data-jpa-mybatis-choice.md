## 두 기술의 관점 차이

JPA는 객체와 관계를 중심으로 데이터 접근을 추상화하는 ORM 표준이다. 구현체인 Hibernate가 Entity 상태와 SQL 생성을 관리한다. MyBatis는 SQL을 직접 작성하고 Mapper를 통해 입력 파라미터와 결과 객체를 연결하는 SQL Mapper다.

| 구분 | JPA | MyBatis |
|---|---|---|
| 중심 | Entity와 객체 관계 | 직접 작성한 SQL |
| SQL 제어 | 추상화 수준이 높음 | 세밀하게 제어 가능 |
| 상태 관리 | 영속성 컨텍스트 | 기본적으로 직접 관리 |
| 복잡한 통계 쿼리 | DTO 쿼리 등 설계 필요 | SQL로 표현하기 편리 |
| 학습 포인트 | 영속성·연관관계·flush | SQL·매핑·동적 쿼리 |

## JPA가 적합한 상황

도메인 객체의 상태 변경이 많고 연관관계를 객체 중심으로 다루는 CRUD 업무에서 생산성이 높다. 변경 감지와 트랜잭션을 활용하면 반복적인 UPDATE 코드를 줄일 수 있다.

다만 N+1, 지연 로딩, flush 시점, 영속성 컨텍스트를 이해하지 않고 사용하면 SQL이 예상과 다르게 실행될 수 있다.

## MyBatis가 적합한 상황

복잡한 JOIN, 집계, 리포트, DB별 SQL 튜닝처럼 SQL을 직접 통제하는 것이 중요한 작업에 적합하다. 대신 SQL과 결과 매핑을 개발자가 관리해야 하며 중복 쿼리와 동적 SQL의 복잡도가 커질 수 있다.

## 한 프로젝트에서 함께 사용할 때

두 기술을 함께 사용할 수 있지만 동일 테이블의 쓰기 책임을 양쪽에 중복으로 두면 상태 추적이 어려워진다. 다음 원칙을 정한다.

1. 업무별 쓰기 책임을 한 기술에 명확히 둔다.
2. 트랜잭션 매니저와 DataSource 구성을 확인한다.
3. JPA 벌크 쿼리와 MyBatis UPDATE가 영속성 컨텍스트를 자동 동기화하지 않는다는 점을 고려한다.
4. 공통 트랜잭션 경계 안에서 두 접근 기술이 같은 DB 트랜잭션에 참여하는지 통합 테스트한다.

**정리:** JPA와 MyBatis 중 무조건 하나가 우수한 것은 아니다. 도메인 상태 관리가 중요한지, SQL 제어가 중요한지, 팀이 쿼리를 관리할 역량이 있는지에 따라 선택한다.
