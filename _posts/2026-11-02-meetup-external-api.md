외부 대중교통 API를 연결하면서 가장 어려웠던 부분은 API를 호출하는 것 자체가 아니라 **외부 데이터 형식을 우리 서비스에서 사용할 수 있는 형태로 바꾸는 것**이었다.

## 외부 API와 내부 모델

외부 API의 응답을 Controller에서 그대로 화면에 전달하면 외부 시스템의 구조가 우리 서비스에 그대로 노출된다.

```text
External API
   ↓
Response DTO
   ↓
Service 변환
   ↓
Domain 형태
   ↓
React
```

이렇게 중간 변환 계층을 두면 외부 API가 바뀌어도 내부 코드의 영향을 줄일 수 있다.

## 막차 문제

첫 번째 지하철 노선의 막차를 탈 수 있다고 전체 귀가가 가능한 것은 아니었다.

```text
A역
 ↓ 1호선 막차
환승역
 ↓
2호선 막차 종료
 ↓
실제 귀가 불가
```

따라서 전체 경로를 단순 문자열로 판단하지 않고 구간별 도착 시간과 다음 환승 가능 여부를 확인해야 했다.

## Redis 캐시

같은 경로를 반복해서 요청하면 외부 API 호출 비용이 커질 수 있어 Redis를 사용했다. 다만 캐시된 데이터가 항상 최신이라는 보장은 없기 때문에 새로고침이나 기준 변경에서는 최신 데이터를 다시 확인하도록 했다.

## 배운 점

외부 API 프로젝트에서는 **API 호출 코드보다 데이터 정규화와 실패 상황을 고려한 도메인 설계**가 더 중요할 수 있다는 것을 배웠다.
