## 5. 탐색 (Search) (1)

탐색(Search)은 데이터 집합에서 원하는 값을 찾는 과정이다.

탐색 알고리즘은 데이터의 정렬 여부와 크기에 따라 적절한 방법을 선택해야 한다.

## 5.1 선형 탐색 (Linear Search)

### 1. 개념

선형 탐색은 배열이나 리스트의 처음부터 끝까지 데이터를 하나씩 확인하면서 원하는 값을 찾는 방법이다.

데이터가 정렬되어 있지 않아도 사용할 수 있다는 장점이 있다.

### 2. 동작 과정

예를 들어 다음 배열에서 `30`을 찾는다고 가정한다.

```text
[10, 20, 30, 40, 50]
```

```text
1단계: 10 확인 → 찾는 값이 아님
2단계: 20 확인 → 찾는 값이 아님
3단계: 30 확인 → 원하는 값 발견!
```

### 3. Java 구현

```java
public class LinearSearch {
    public static int search(int[] arr, int target) {
        for (int i = 0; i < arr.length; i++) {
            if (arr[i] == target) {
                return i;
            }
        }

        return -1;
    }

    public static void main(String[] args) {
        int[] arr = {10, 20, 30, 40, 50};

        int index = search(arr, 30);

        System.out.println(index); // 2
    }
}
```

- 찾는 값을 발견하면 해당 인덱스를 반환한다.
- 끝까지 찾지 못하면 `-1`을 반환한다.

### 4. 시간 복잡도

| 경우 | 시간 복잡도 | 설명 |
|---|---|---|
| 최선 | O(1) | 첫 번째 위치에서 발견 |
| 평균 | O(n) | 평균적으로 여러 요소 확인 |
| 최악 | O(n) | 마지막까지 확인하거나 값이 없음 |

### 5. 특징

- 데이터가 정렬되어 있지 않아도 사용할 수 있다.
- 구현이 간단하다.
- 데이터가 많아질수록 탐색 시간이 증가한다.

## 5.2 이진 탐색 (Binary Search)

### 1. 개념

이진 탐색은 정렬된 데이터에서 탐색 범위를 절반씩 줄여가며 원하는 값을 찾는 방법이다.

선형 탐색과 달리 **데이터가 반드시 정렬되어 있어야 한다.**

### 2. 동작 원리

다음 배열에서 `70`을 찾는다고 가정한다.

```text
[10, 20, 30, 40, 50, 60, 70, 80, 90]
```

탐색에 사용하는 변수는 다음과 같다.

- `left`: 탐색 범위의 시작 인덱스
- `right`: 탐색 범위의 마지막 인덱스
- `mid`: 탐색 범위의 중간 인덱스

```text
1단계: 중간값 50 확인

[10, 20, 30, 40, 50, 60, 70, 80, 90]
                    ↑
                   mid

70 > 50 이므로 왼쪽 범위 제거
```

```text
2단계: 남은 오른쪽 범위에서 중간값 70 확인

[60, 70, 80, 90]
     ↑
    mid

70 == 70 이므로 탐색 성공!
```

### 3. 동작 과정

1. 탐색 범위의 시작과 끝을 설정한다.
2. 중간 인덱스를 계산한다.
3. 중간값과 찾는 값을 비교한다.
4. 찾는 값이 더 크면 왼쪽 범위를 제거한다.
5. 찾는 값이 더 작으면 오른쪽 범위를 제거한다.
6. 값을 찾거나 탐색 범위가 없어질 때까지 반복한다.

### 4. Java 구현

```java
public class BinarySearch {
    public static int search(int[] arr, int target) {
        int left = 0;
        int right = arr.length - 1;

        while (left <= right) {
            // 정수 오버플로를 방지하는 중간 인덱스 계산
            int mid = left + (right - left) / 2;

            if (arr[mid] == target) {
                return mid;
            } else if (arr[mid] < target) {
                // 찾는 값이 더 크므로 오른쪽 탐색
                left = mid + 1;
            } else {
                // 찾는 값이 더 작으므로 왼쪽 탐색
                right = mid - 1;
            }
        }

        return -1;
    }

    public static void main(String[] args) {
        int[] arr = {10, 20, 30, 40, 50, 60, 70, 80, 90};

        int index = search(arr, 70);

        System.out.println(index); // 6
    }
}
```

### 5. 시간 복잡도

| 경우 | 시간 복잡도 | 설명 |
|---|---|---|
| 최선 | O(1) | 첫 번째 중간값에서 발견 |
| 평균 | O(log n) | 탐색 범위를 반복적으로 절반으로 축소 |
| 최악 | O(log n) | 마지막 단계까지 탐색하거나 값이 없음 |

데이터가 1,000개라면 약 10번의 탐색으로 범위를 좁힐 수 있다.

```text
1,000 → 500 → 250 → 125 → ... → 1
```

### 6. 특징

- 반드시 정렬된 데이터에서 사용해야 한다.
- 탐색할 때마다 범위가 절반으로 줄어든다.
- 데이터가 많을수록 선형 탐색보다 효율적이다.
- 배열처럼 인덱스로 중간 위치에 바로 접근할 수 있는 자료구조에 적합하다.

## 5.3 선형 탐색과 이진 탐색 비교

| 구분 | 선형 탐색 | 이진 탐색 |
|---|---|---|
| 탐색 방식 | 처음부터 하나씩 확인 | 중간값을 기준으로 범위 축소 |
| 정렬 필요 여부 | 필요 없음 | 반드시 필요 |
| 최선 시간 복잡도 | O(1) | O(1) |
| 평균 시간 복잡도 | O(n) | O(log n) |
| 최악 시간 복잡도 | O(n) | O(log n) |
| 구현 난이도 | 쉬움 | 상대적으로 어려움 |

### 어떤 탐색을 사용해야 할까?

- 데이터가 정렬되어 있지 않다면 → 선형 탐색
- 데이터가 정렬되어 있고 크기가 크다면 → 이진 탐색
- 데이터가 적고 구현이 간단한 방법이 필요하다면 → 선형 탐색
- 배열처럼 인덱스 접근이 빠른 자료구조라면 → 이진 탐색 활용

## 핵심 정리

| 개념 | 핵심 내용 |
|---|---|
| 선형 탐색 | 데이터를 처음부터 하나씩 확인 |
| 이진 탐색 | 중간값을 기준으로 탐색 범위를 절반씩 축소 |
| 선형 탐색 시간 복잡도 | O(n) |
| 이진 탐색 시간 복잡도 | O(log n) |
| 이진 탐색 조건 | 데이터가 정렬되어 있어야 함 |

**핵심 포인트:** 탐색 알고리즘은 데이터의 정렬 여부와 크기를 고려하여 선택해야 한다.
